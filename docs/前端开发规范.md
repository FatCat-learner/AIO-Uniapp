# AIOSport 前端开发规范（aio-uni-app-x）

> 适用范围：`aio-uni-app-x`（uni-app + Vue 3 + Vite + TS + pinia + uview-plus）。
> 本文是**硬约束**，新增/改造页面一律按此执行；评审时以本文为准。
> 起因：`pages/discover/discover.vue` 曾膨胀到 1526 行（template 462 / script 288 / style 774），

## 1. 目录分层总览

```
src/
├─ pages/<page>/          # 页面：只放布局骨架 + 粘合逻辑
│  ├─ <page>.vue          #   页面文件（index.vue 也可，同一项目保持一种）
│  ├─ config/             #   页面私有：常量、种子、类型、字段映射、行/列描述规则
│  │  ├─ index.ts         #     统一出口 export * from './xxx'
│  │  ├─ types.ts         #     页面内类型（Sec / RailItem / Row 联合…）
│  │  ├─ seed.ts          #     静态种子数据、枚举常量、接口端点映射
│  │  └─ <page>.ts        #     该页特有的展示配置（分类定义、维度配置…）
│  └─ components/         #   页面私有子组件（不跨页复用，不进 src/components）
├─ store/<feature>/       # 状态：index.ts + types.ts，与页面/业务同名
├─ api/<feature>/         # 接口：index.ts + types.ts，与页面/业务同名
├─ utils/                 # 与业务无关的通用纯工具（函数 / 极薄封装）
├─ composables/           # 与业务无关的通用有状态逻辑（useXxx）
├─ components/base|layout|home|auth   # 跨页复用的 UI 组件（≥2 处真实复用才准入）
└─ styles/theme.scss      # 设计令牌唯一来源（浏览器副本 _design/tokens.css）
```

**依赖方向（单向，不许反向或跨层）**

```
pages/*.vue → pages/*/components → store → api → (mocks | 后端)
pages/*/config ← 页面与组件（只被读，不 import 任何上层）
utils / composables ← 所有层（被读，不 import 业务）
```

硬规则：

- 页面 / 组件**禁止直接 import `@mocks/*`**，种子数据只允许出现在 `src/api/<feature>/`。
- store **禁止** import `@mocks/*`，也不直接 new 请求，只调 `src/api/<feature>`。
- `config/` 只放常量与类型，**不放函数副作用**（纯映射函数可以有，不调 uni API）。
- `utils/` **禁止**出现业务名词（`CATS`、`rail`、`pom`、`kcal` 这类一律回 `config/`）。

## 2. 单文件体积红线

| 文件 | 上限 | 超了怎么办 |
| --- | --- | --- |
| `.vue`（template+script+style 合计） | **300 行** | 按 §3 的切分顺序拆 |
| `<script setup>` | **150 行** | 常量/类型→`config/`，状态→store，纯函数→utils |
| `<style scoped>` | **200 行** | 标记搬到哪个组件，就带哪段样式走 |
| `config/*.ts`、`store/*.ts`、`api/*.ts` | 200 行 | 按职能再分文件（types / seed / mapping） |
| `utils/*.ts` 单个导出函数 | 40 行 | 拆函数，不要写上帝函数 |

> 500 行以上的 `.vue` 视为**不合规**，Code Review 直接打回。`discover.vue` 就是反例。

### 切分优先级（从上往下，先试前面的）

1. **常量 / 类型 / 枚举 / 字段映射** → `pages/<page>/config/`（页面私有）或 `src/api/<feature>/types.ts`（契约）。
2. **与业务无关的纯函数**（字符串、数组、时间、格式化）→ `src/utils/<domain>.ts`。
3. **与业务无关的有状态逻辑**（滚动监听、倒计时、防抖、弹层开关机）→ `src/composables/useXxx.ts`。
4. **页面私有 UI 块**（一个 tab 栏、一个弹层、一行列表）→ `pages/<page>/components/Xxx.vue`。
5. **跨页复用 UI**（≥2 个页面真实用到）→ `src/components/`（先查 uview-plus 有没有现成组件，见 AGENTS.md 的选型阶梯）。

### 「通用」的判定标准（三条全满足才算）

- 至少 **2 处真实调用**（现役代码里数得出来，不是"以后可能用"）；
- 函数签名里**没有业务名词**（品类、肌群、餐次、维度名…）；
- 不依赖页面上下文（不读 `getCurrentInstance`、不读 pinia store、不 import `config/`）。

只满足一两条的，留在 `pages/<page>/config/` 或页面里，不要往全局塞。

## 3. 页面标准骨架（四件套）

新建页面 `xxx` 必须**同时**产出四个同名产物，缺一不可：

```
src/pages/xxx/
├─ index.vue                # 或 xxx.vue，全项目统一
├─ config/
│  ├─ index.ts
│  ├─ types.ts
│  └─ seed.ts               # 可无，视是否要种子
└─ components/              # 可无，视页面复杂度
src/store/xxx/
├─ index.ts                 # export default useXxxStore
└─ types.ts
src/api/xxx/
├─ index.ts                 # 与 store 同名的一组请求函数
└─ types.ts                 # 请求/响应类型（= 后端契约）
```

**命名一致规则（重要）**

| 位置 | 命名 | 例（页面 discover） |
| --- | --- | --- |
| 页面目录 | kebab-case | `src/pages/discover/` |
| pinia id | 与页面同名 | `defineStore('discover', …)` |
| store 目录 / 导出 | 同名 / 驼峰 + Store | `src/store/discover/index.ts` → `useDiscoverStore` |
| api 目录 | 同名 | `src/api/discover/index.ts` |
| 请求函数 | 动词开头，无前缀 | `getCatalog` / `fetchCatalog` / `toggleFavorite` |
| 类型 | 契约用 `I` 前缀（沿用 auth），页面内类型不加前缀 | `ICatalogQuery` / `Sec` |

页面名 = store 名 = api 目录名，三者必须能互相猜出来。**不要**出现 `pages/data` 却调用 `store/catalog` 这种错位。

唯一已存在的例外：首页目录是 `pages/index`，但它不能叫 `store/index`（与 pinia 根 `src/store/index.ts` 的路径解析冲突），所以首页域统一命名 `home`（`store/home`、`api/home`）。新增页面时别再制造这种特例——**页面目录不要用 `index` 这种会和 barrel 撞名的词**。

### 例外：共享业务域不建页面专属 store/api

「一页一 store 一 api」的前提是**这个页面的状态和接口属于它自己**。当一个业务域横跨多个页面时，api/store 按**域**建，不按页面建——否则 `api/login`、`api/register`、`api/reset-password` 会各自复制一份同一套接口契约，改一个忘两个。

| 场景 | 该怎么做 |
| --- | --- |
| 页面属于已有域（如 auth 流：login / code-login / register / reset-password） | 共用 `src/api/auth/`、`src/store/auth/`，页面目录只建 `config/` + `components/` + `styles/` |
| 页面有自己的状态与接口 | 建 `src/store/<name>/` + `src/api/<name>/`（完整四件套） |
| 纯静态展示页（无接口、无跨组件共享状态） | 只建 `config/`（+ 大块 `components/`），不建 store/api，在 PR 说明里写清楚为什么不建 |

判据是「数据归属」不是「有没有出现页面目录」：**同一个后端契约只能有一个 api 模块**，同一个业务状态只能有一个 store。

### 生成方式

```bash
pnpm gen:page total "总计"      # 生成页面 + config + components + store + api，并在 pages.json 注册
```

脚本产物即是本规范的最小可运行骨架，生成后按需往里填内容——**不要手工复制旧页面再删代码**。

## 4. 数据流与 store 边界

```
组件（纯展示，props in / emits out）
   ↕                    ← 页面向下传 props、向上收 emit
页面 <page>.vue（布局 + 事件路由）
   ↕                    ← storeToRefs 取状态，调 action
store/<feature>（状态 + 派生 + 业务编排）
   ↕
api/<feature>（请求 / mock 适配，唯一知道 URL 与 mock 种子的一层）
```

**什么进 store**

- 跨组件共享的状态（当前品类、选中筛选项、收藏表、搜索词）；
- 由共享状态算出来的派生值（分区列表、左栏项、跨 tab 命中数）→ 写成 **getter**，不要在每个组件里重算；
- 业务动作（切品类、切筛选、收藏、扫描流程）→ 写成 **action**。

**什么不进 store**

- 纯 UI 临时态：弹层开合动画中间态、滚动位置、toast 文案、定时器句柄；
- 只在一个组件里用的局部变量；
- 请求中的 loading 标记（除非多个组件都要显示）；放页面 ref 即可。

**页面允许直接调 api 的例外**：一次性、无状态、不产生共享状态的查询（例如首页的一次性埋点上报）。除此之外一律走 store。

## 5. store 写法模板（setup store）

```ts
// src/store/discover/index.ts
import type { Sec, RailItem } from './types';
import type { CatKey } from '@/pages/discover/config';
import { defineStore } from 'pinia';
import { getCatalog, toggleFavorite } from '@/api/discover';
import { FAV_SEED } from '@/pages/discover/config';

export const useDiscoverStore = defineStore('discover', () => {
  // --- state ---
  const cat = ref<CatKey>('action');
  const favs = reactive<Record<string, boolean>>({ ...FAV_SEED });

  // --- getters（computed，只读派生，不做副作用）---
  const curCat = computed(() => CATS.find(c => c.key === cat.value)!);
  const sections = computed<Sec[]>(() => { /* 纯计算 */ });

  // --- actions（改状态 / 调 api）---
  function switchCat(k: CatKey) { /* ... */ }
  async function loadRows() { /* getCatalog → rows */ }

  return { cat, favs, curCat, sections, switchCat, loadRows };
});
```

- `defineStore` 由 unplugin-auto-import 提供（依赖 `imports: ['vue','uni-app','pinia']`），显式 import 也对，保持文件内一致即可。
- `persist: true` 只在**确实需要本地持久化**时加（如登录态）；列表/筛选状态不要持久化，否则用户回到页面会看到过期筛选。
- 组件里取 store 状态必须 `storeToRefs`（或 `computed`），**不要**直接解构，否则丢响应性。

## 6. api 写法模板

```ts
// src/api/discover/types.ts
import type { CatKey } from '@/pages/discover/config';
export interface ICatalogQuery { keyword?: string; page?: number; pageSize?: number; }

// src/api/discover/index.ts
import { get, post } from '@/utils/request';
import { ACTIONS, FOODS, PLANS, ROUTES } from '@mocks/data/catalog';

/** 同步种子（未接后端前的默认数据源） */
export function getCatalog(cat: CatKey) { … }

/** 接后端后的真实请求，返回分页结构 */
export function fetchCatalog(cat: CatKey, params: ICatalogQuery) {
  return get<PageResult<Row>>(CAT_ENDPOINT[cat], { params });
}
```

- URL 只在 `api/` 出现一次；页面与 store 里不许出现字符串 URL。
- 请求/响应类型写 `api/<feature>/types.ts`；与后端契约同口径，**不要**在页面里另起一套 interface。
- mock 口径以 `mocks/` 为准（见 `mocks/README.md`）：dev 下由 vite-plugin-mock 拦截，`env/.env.development` 里 `VITE_APP_MOCK=false` 可关闭。
- 一期未接后端时，api 层返回 `mocks/data/*` 的同步种子；**同时**把 `async fetchXxx()` 留好，页面切换数据源时只改 store 里一行。
- 错误处理交给 `utils/request` 的拦截器；api 层不做 toast，是否提示由调用方决定。

## 7. 样式规则

- **颜色 / 字号 / 间距 / 圆角 / 阴影只引令牌**：`src/styles/theme.scss` 的 CSS 变量（`var(--brand-500)` 等），浏览器副本 `_design/tokens.css`。禁止页面里写死十六进制色值。
- 令牌改动：改 `theme.scss` → `node _design/sync-tokens.mjs`（在仓库根执行）→ `--check` 通过。
- **样式跟着标记走**：把一段模板搬进子组件时，对应的 scss 规则一起搬进该组件的 `<style scoped>`。父页面只留布局类。禁止用 `:deep()` 兜底"父页面管子组件内部"。
- 一个组件一个根元素（scoped 样式才不会漏到外面）。
- 主题色透传用 CSS 变量继承：父级 `:style="{'--acc': …}"`，子组件里直接 `var(--acc)`；不要用 props 传色值。

### selectorQuery 的平台坑（必须记住）

`uni.createSelectorQuery().in(inst.proxy)` 在**小程序端只能查到当前组件实例内的节点**，查不到子组件里的节点。
所以凡是 `measure()` / 滚动锚点 / `boundingClientRect` 依赖的节点（`.main`、`.sec` 等），
**必须留在页面模板里**，不能整体抽进子组件；只能把内部的行元素抽成 `XxxRow.vue`。
需要跨组件测量时，用 `defineExpose` 把测量方法暴露给页面，由页面在自己的 `proxy` 上调。

## 8. 自动导入与显式 import

| 能力 | 来源 | 是否需 import |
| --- | --- | --- |
| `ref/computed/reactive/watch/nextTick/onMounted/getCurrentInstance/defineStore/storeToRefs…` | `build/plugins/autoImport.ts`（`imports: ['vue','uni-app','pinia']`） | 不用 |
| `uni.*` API | uni-app 全局 | 不用 |
| `u-button` 等 uview-plus 组件 | easycom autoscan（`pages.json`） | 不用 |
| `src/components/**` 下的项目组件 | `unplugin-vue-components`（默认目录 `src/components`） | 不用 |
| `pages/<page>/components/**` 页面私有组件 | 不在扫描目录内 | **必须显式 import** |
| `@/api`、`@/store`、`@/utils`、`@/composables` | — | **必须显式 import** |

`tsconfig` 开了 `verbatimModuleSyntax` + `noUnusedLocals`：类型一律 `import type`，不留未使用的导入与变量。

## 10. 反例与教训（discover 页）

| 症状 | 根因 | 现在的做法 |
| --- | --- | --- |
| `discover.vue` 1526 行 | 常量、派生、动作、774 行样式、8 个 UI 块全塞一个文件 | 布局留页面；配置进 `config/`；状态进 `store/discover`；种子进 `api/discover`；UI 块进 `pages/discover/components/` |
| 收藏种子写死在页面，接接口要翻半天 | 数据源散落 | 种子只在 `api/discover`；页面不 import mocks |
| `rowMeta` 的 if/else 越长越乱 | 分支里混了字段知识 | 变成 `config/` 的字段映射表 `ROW_META`，加品类只加一行 |
| 滚动高亮 `measure()` 抽组件后小程序失效 | selectorQuery 只查本组件 | `.sec`/`.main` 留在页面，只抽行组件（§7 平台坑） |
| 样式跟着标记搬不走，`scoped` 直接失效 | 只搬模板不搬样式 | 搬一段标记 = 搬一段样式，父页面只留布局类 |

## 11. 强制格式与踩坑（lint 会卡你的地方）

- **SFC 块顺序必须是 `template` → `script` → `style`**：`eslint.config.mjs` 的 `vue/block-order` 是 error 级，脚本在前 `pnpm lint` 直接判错；`pnpm gen:page` 已按这个顺序出骨架。
- **大括号走 stroustrup 风格**：`}` 单独一行，`catch` / `finally` 另起一行（`style/brace-style`），仓库现有写法见 `src/utils/storage/index.ts:18-19`。
- **语句必须有分号**（`style/semi`）；**多行必须有尾随逗号**（`comma-dangle: only-multiline`）；块内不留空行（`padded-blocks: never`）。
- **自定义事件用 camelCase 声明**（`vue/custom-event-name-casing`），父模板里继续写 `@select-rail` 这种 kebab 没问题。
- **props 写法二选一**：`defineProps<Props>()` 或带 `withDefaults` 的类型写法，同一个组件别混着来。
- **`pnpm lint` 全仓库已可运行（2026-10-25 修好）**：之前 `@unocss/eslint-plugin` 加载配置时会把 `src/layouts/README.md` 当模块 import，抛 `ERR_UNKNOWN_FILE_EXTENSION ".md"`；根因是 `eslint.config.mjs` 的 ignores 只写了 `'README.md'`（仅匹配根目录），已改成 `'**/README.md'`。**别再把 ignores 写成只匹配根目录的裸文件名**，新增带 `.md` 的目录也会踩同一脚。
- **别忽略 `eslint --fix` 的批量重排**：修好崩溃后全仓库首次暴露 426 个 problem（404 可自动修），一次性 `npx eslint src --fix` 重排了约 30 个文件。之后新增代码必须保持零报错，别再攒到下一次。
- **stylelint 认 BEM**：`stylelint.config.js` 默认继承 `stylelint-config-standard-scss` 的 `selector-class-pattern`（只认 kebab），会否掉全项目 `block__element--modifier` 的写法（首次跑报 980 个）。已加规则覆盖：允许 `kebab` / `block__element` / `block--modifier`，`resolveNestedSelectors: true`。**新写类名照这个来**，别引入第三种命名。
- **样式声明顺序由 `stylelint-config-recess-order` 管**：`pnpm stylelint:fix` 会自动重排（首轮重排了几乎全部 scss）。写完 scss 直接跑 fix，别手排。
- **禁止重复声明同名属性**（`declaration-block-no-duplicate-properties`），例如同一个选择器里写两遍 `backdrop-filter`。
- **lockfile 与 `node_modules` 漂移，会让所有 `pnpm <script>` 直接罢工**（`ERR_PNPM_VERIFY_DEPS_BEFORE_RUN`，连 `pnpm lint` 都跑不了）。典型场景：有人手动装了包、或手改了 `package.json` 依赖却没同步 `pnpm-lock.yaml`。
  两种修法：① 手改错了 → **用 `node_modules/.pnpm/lock.yaml` 覆盖回 `pnpm-lock.yaml`**（那份是上次真实安装用的 lock，天然和本地 `node_modules` 一致），再把同一依赖写回 `package.json`；② 想真装依赖 → 直接 `pnpm install`（overrides 已在 `pnpm-workspace.yaml`，不会再被丢）。
- **临时绕过（仅应急）**：`pnpm --config.verify-deps-before-run=false <script>`。别用它长期掩盖漂移。

### 13.2 层叠（只有这一张表）

`overlayStack.ts` 的 `overlayZ()`：`mask 20 / sheet 30 / dialog 32 / menu 34 / toast 40 / coach 44 / topNotice 48`。

- 禁止页面里写裸 `z-index`（历史遗留 900 / 950 / 999 在迁移时替换）。
- 页面滚动锁用 `lockPageScroll()` / `unlockPageScroll()`，计数式；不要再手动改 `body.style.overflow`。
- `theme.scss` 不提供 `--z-*`：z-index 要参与 JS 判断（叠层、翻转），放 TS 常量表里。
- 浮层配色只认 4 个令牌：`--danger-soft` / `--danger-line` / `--warn-soft` / `--info-soft`（后三个 2026-10-25 新增，与 `tokens.css` 同步）。

### 13.3 输入法（硬约束，真机必测）

| 规则 | 写法 | 为什么 |
| --- | --- | --- |
| 键盘高度只从 `useKeyboardInset()` 取 | `const kb = useKeyboardInset()` | 多处各自 `uni.onKeyboardHeightChange` 会互相覆盖 |
| 输入框必须关掉系统顶页 | `adjust-position="false"` | 系统顶页会把遮罩一起顶出屏幕 |
| 输入框与键盘留距 | `cursor-spacing="24"`（表单）/ `"12"`（搜索） | 防「贴着键盘打字」 |
| 键盘动作语义 | `confirm-type="done"/"next"/"search"` | 少一次手动收起 |
| 关闭浮层前先收键盘 | `kb.hide()` → 再关 → 组件内 `kb.reset()` | 部分 Android 收起不上报 0，不复位留空白 |
| H5 无软键盘 | `visualViewport` 兜底，值可能是 0 | 布局不能假设 `height > 0` |

半屏：面板 `translateY(-键盘高度)`，高度不变，正文区自己滚。中心弹窗：整体上移到顶部安全距离（`is-lifted`），不缩放。
